## Why "repo" still exists (Architect - the crux prior attempts dodged)

"repo" persists for exactly two reasons, both hardcoded into add-ons already on the boxes:

1. **Proxy** `repo/repository.tony7bones/resources/repository.json` - 22 `/repo/` path
   segments; the manifest is **baked into the installed add-on** (`lib/service.py:26`), read
   at runtime via **raw.githubusercontent** from the git tree (`lib/repository.py:236-243`).
2. **Bootstrap** `repo/script.tony7bones.bootstrap/default.py:63-64` -
   `REPO_BASE="…/repo/repositories/"`, `STATIC_BASE="…/repo"` (hit **Pages**).

Making "repo" vanish AND keeping functionality therefore **requires re-pointing and
re-releasing those two add-ons**, with a migration so installed boxes transition safely.
Keeping `repo/` as a hidden compromise is explicitly rejected by the owner.

> Note: the proxy reads the **git tree via raw**, which is independent of the Pages root
> listing - so renaming `repo/`→`addons/` is a _choice_ to satisfy the "no repo string"
> bar, not a technical requirement for serving. **Confirm the exact bar with the owner**
> (is "not shown in the listing" enough, or must the string `repo` not appear in any served
> path?). That answer decides Decision A below.

## Band-aids to remove (both agents)

- `_tools/generate_repo.py` `sync_dropbox()` (~line 284): mirrors the canvas **two ways** -
  each subfolder → `repo/<folder>/` AND the whole canvas → `repo/dropbox/`. This is the
  on-disk **duplication** (`repo/repositories/` _and_ `repo/dropbox/repositories/`, etc.).
- `.githooks/pre-commit`: copies the proxy zip into `dropbox/repositories/`, rebuilds, then
  **`git add -A`** (can sweep unintended files - review staged diff before any push).
- Root `index.html` links `repo/dropbox/` (the only reason the canvas is reachable, and it's
  nested under `repo/`). Stale `repo/index.html` advertises an old `1.0.5` install path.

## Target architecture (Architect - recommended)

- Serve the canvas **at the site root**: bare `https://tony7bones.github.io/` returns a
  generated `index.html` listing exactly `dropbox/`'s entries. Single source of truth =
  `dropbox/`; no `repo/dropbox/`, no per-folder mirror.
- Machine/add-on source (proxy, Setups, library, `hosted/`, `addons.xml`, `_tools/`) stays
  committed to `main` (proxy fetches it from the git tree) but is **renamed `repo/`→`addons/`
  and never linked from the root** (Decision A, option 1).
- **Keep legacy branch-serving of `main`; do NOT add a Pages Actions build.** The proxy reads
  the git tree and `deploy.py` assumes "committed == served"; an Actions build would create
  two sources of truth and break deploy's live-verify. The clean root listing should be
  generated by `generate_repo.py` at commit time and committed.

## What must be done (Architect - ordered; `[LIVE]` = touches boxes)

5. **Remove band-aids**: pre-commit `git add -A`/zip-mirror, `repo/dropbox/`, per-folder

## Migration so no box breaks (Architect)

Old boxes run proxy v2.2.0 (fetch `…/main/repo/…`) + old bootstrap (fetch `…/repo/…`).
Keep **both old and new paths alive** through a transition window:

1. Add the new layout **alongside** `repo/` (leave `repo/` intact).
2. Release new proxy (step 2) → boxes self-update on Kodi's refresh cycle.
3. Release new bootstrap (step 3) → installed-on-demand, self-uninstalls, lower risk.
4. **Wait the window** (no telemetry; manually confirm a representative box, or leave weeks).
5. **Only then** remove `repo/` + band-aids (do this last, alone, easily revertible).

Rollback per live step: ship a **higher** version reverting the manifest/paths (the
dist→main revert `5e4bf5c` already proved this works); root flip + `repo/` deletion are
plain commit reverts.
